## Findings

### Stale Inventory Counts
- [`AGENT_REFERENCE.md`]: The agent table lists **7 agents**. Per the document's own Recent Changes, the
  correct count is **8** — 7 listed, minus `legacy-formatter` (removed in v1.6 but still present), plus
  `sre-engineer` (v1.8) and `visual-qa-engineer` (v1.7), which are absent.

  The document has been **at least three versions out of date since v1.6**, and the drift is compounding
  rather than being corrected: three separate releases each added a discrepancy and none reconciled the
  table.

### Un-Indexed Agents
- [`shared/agents/sre-engineer.md`]: Added in v1.8 and **not listed** in the agent table. The document's own
  Recent Changes says so explicitly.
- [`shared/agents/visual-qa-engineer.md`]: Added in v1.7 and **not listed**. Same self-report.

  Both are pipeline agents with a defined position in the delivery sequence (`sre-engineer` after developer,
  before devops; `visual-qa-engineer` after qa-engineer). Their absence from the reference is worse than a
  missing row: the table's "Invocation" column documents the pipeline *order*, so as printed it describes a
  pipeline that runs code-reviewer → qa-engineer → tech-writer → devops-engineer with no observability pass
  and no visual QA. A reader following this table would build the wrong pipeline, not merely an incomplete
  list.

### Deprecated Entries Still Listed
- [`AGENT_REFERENCE.md`]: **`legacy-formatter` was removed in v1.6 and is still in the table**, annotated
  "(deprecated)" with invocation "Manual only". Two problems, and they compound: the agent does not exist,
  so any attempt to invoke it fails; and the "(deprecated)" annotation actively implies it still *works*,
  just discouraged. Removed and deprecated are different states, and documenting the second when the first
  is true is the more misleading of the two errors.

- [`AGENT_REFERENCE.md`]: The skills list contains **`/epic-planner` — DEPRECATED — replaced by
  /spec-writer in v1.9**. This one is handled *correctly* and is worth calling out as such: it names the
  replacement and the version. That is exactly what the `legacy-formatter` row should look like, or the row
  should be gone. The inconsistency within a single document — one deprecation documented well, another
  documented as though it were still available — is itself the finding.

  One open question a human should settle: `/epic-planner` is marked deprecated as of **v1.9**, while
  `legacy-formatter` was removed in **v1.6**. If the project's convention is that deprecated entries are
  retained for one or two versions and then deleted, `legacy-formatter` is three versions past its removal
  and `/epic-planner`'s entry may be current and correct. **This audit cannot tell which policy applies**
  because no deprecation policy is stated in the excerpt — flagged rather than assumed.

### Verification Not Possible In This Run

- No independent scan of `shared/agents/` or `shared/skills/` was performed; every count above derives from

- The skills list shows only three entries, which is implausibly few for a framework of this shape. It is

      invocation path that cannot work.
- [ ] **Add `sre-engineer` and `visual-qa-engineer` rows**, with their correct pipeline positions in the
