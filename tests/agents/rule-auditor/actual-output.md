## Findings

### Cross-Rule Contradictions
**None.** Three overlaps were checked, and all three are consistent:

- **`any` in TypeScript**: `typescript-conventions.md` says "`strict: true` in `tsconfig.json`, no raw
  `any`". `architecture-guardrails.md` #4 says "No raw `any` types allowed in TypeScript. If you genuinely
  don't know the type, use `unknown` with runtime narrowing/Zod validation." **Consistent** — the guardrail
  states the constraint and the escape hatch; the conventions file states the constraint and the tooling
  that enforces it. Neither permits what the other forbids.

  This is redundancy, not contradiction, and it is the *good* kind: `typescript-conventions.md` explicitly
  cross-references `architecture-guardrails.md` #4 rather than restating it independently. A reader who
  finds the rule in either place is pointed at the authority. **No action.**

- **Cyclomatic complexity**: `design-principles.md` and `CLAUDE.md` both say "< 7"; `CLAUDE.md` adds "no
  exceptions" and specifies "ESLint complexity rule: max 6 (enforces the < 7 rule)". **Consistent, and the
  arithmetic is right** — an ESLint cap of 6 means a function of complexity 7 fails, which is exactly what
  "< 7" requires. A cap of 7 would have permitted 7 and been an off-by-one contradiction; it is worth
  recording that this was checked, because it is the single most likely place for these two files to have
  silently disagreed.

- **Test coverage and TDD**: `testing-conventions.md` says "NEVER write feature code without tests" and
  "coverage MUST be >= 85%". `CLAUDE.md` says ">= 85% for everything in `src/` and `lib/`". **Consistent**,
  with `CLAUDE.md` supplying the scope the conventions file leaves open. Worth noting the *asymmetry*:
  `testing-conventions.md` states the threshold without a scope, so read alone it implies 85% across all
  code including tests and generated files. Not a contradiction — a scope gap that `CLAUDE.md` happens to
  fill. Flagged as a clarity improvement, not a conflict.

### Dead File References (Critical)

- [`shared/rules/go-conventions.md`] references **`docs/DOMAIN_DICTIONARY.md`**, while
  [`shared/rules/design-principles.md` §6] references **`DOMAIN_DICTIONARY.md`** (repository root, no path
  prefix).

  **These cannot both be correct.** The file is in one location, so one of these two references is dead —
  and whichever it is, an agent following it silently fails to load the Ubiquitous Language and then writes
  code with unvalidated domain terms. The failure is quiet, which is what makes it worth the Critical
  heading: no error is raised, the dictionary is simply not consulted, and the ubiquitous-language check
  that both files exist to enforce does not happen.

  **Which one is dead could not be determined here** — this excerpt does not include a directory listing and
  the file is not present in this repository, so a `Glob` resolution was not possible. The root-level form
  is the more likely correct one on two weak signals: `CLAUDE.md` and the framework's other references use
  the bare name, and `DOMAIN_DICTIONARY.template.md` is described elsewhere as a root-level template. Weak
  signals, offered as a starting point rather than a conclusion. **A human should resolve the actual path
  and make both references match it.**

  Worth noting this is a *path* inconsistency, not a semantic one: both files use the dictionary for the
  same purpose (ubiquitous-language alignment) and neither contradicts the other about what it is for.

### Un-Indexed Rule Files

- [`shared/rules/iac-conventions.md`] exists on disk but is **not listed in any rules index or in
  `CLAUDE.md`'s load order**.

  The consequence is specific and worse than it first appears. Agent prompts open with an explicit list —
  "read `design-principles.md`, `architecture-guardrails.md`, and `approval-gates.md`" — so **rules are
  loaded by enumeration, not by directory scan.** A rule file absent from every index is not merely
  under-advertised; it is *never loaded by any agent*. It exists, it is maintained, and it has no effect.

  This matters more than a typical indexing gap because of what is in that file: `iac-conventions.md`
  carries the Terraform, Dockerfile, Kubernetes, and GitHub Actions rules — including
  no-`latest`-base-images, non-root `USER`, SHA-pinned actions, explicit `permissions:` blocks, and the
  `pull_request_target` warning. Those are security constraints, and the `devops-engineer` agent, which is
  the one that needs them, will not be loading them unless its own prompt names the file directly. **Whether
  it does could not be checked from this excerpt** — `devops-engineer.md` is not quoted here — so this is
  reported as an indexing gap with a probable-impact statement rather than a confirmed unloaded-rule
  finding.

### Redundancy Assessment
The excerpt's framing suggests some of these overlaps might be "redundant constraints" to be eliminated.
Recommending against that, deliberately: the duplication between `CLAUDE.md` and the `shared/rules/` files
is **layered by design** — `CLAUDE.md` is the always-loaded summary and the rules files are the detail. The
right hygiene target is not deduplication but **directionality**: each rule should have one authoritative
home, with other mentions cross-referencing it rather than restating it independently.
`typescript-conventions.md` → `architecture-guardrails.md` #4 is the model; the complexity rule, stated
fully in both `design-principles.md` and `CLAUDE.md` with no cross-reference between them, is the one most
at risk of drifting.
