## Findings

### Unmatched Queries (Missing KI / Tag Gaps)

- Query `"expand contract migration"` returned **0 hits**. The registry confirms no KI carries tags
  `[expand-contract, migration, database]`. **Recommended subject for `create-ki` — highest priority of the
  three.**

  This is the most consequential gap in the corpus. Expand/Contract is a **hard constraint** —
  `architecture-guardrails.md` #2 forbids `DROP COLUMN`, `RENAME COLUMN`, `DROP TABLE`, and `NOT NULL`
  without `DEFAULT` in a single phase — and every language convention file repeats the requirement. So the
  framework mandates a pattern at its strictest level and holds **zero retrievable knowledge about how to
  execute it**. An engineer who queries for it is doing exactly the right thing and gets nothing back;
  their fallback is to improvise a phased migration, which is where 8-million-row table locks come from.
  The rule is enforced; the technique is undocumented.

- Query `"circuit breaker retry"` returned **0 hits**. No KI carries `[circuit-breaker, resilience, retry]`.
  **Recommended subject for `create-ki`.**

  Same shape, same severity class. `architecture-guardrails.md` #5 bans hand-rolled retry loops and
  *requires* a framework-provided `CircuitBreaker` or `ExponentialBackoffStrategy`. A developer told they
  must use a specific resilience primitive, who then searches for how to use it and finds nothing, will
  write the `for` loop with `sleep` that the rule prohibits. **A banned alternative with no documented
  replacement is a rule that will be broken by well-intentioned people**, and this query is the corpus
  telling us that is happening.

- Query `"WebSocket fanout multi-instance"` returned **0 hits**. No KI carries `[websocket, fanout,
  pub-sub]`. **Recommended subject for `create-ki` — but with a different justification from the first
  two.**

  Unlike the others, no framework rule mandates a WebSocket fanout approach. What makes this query valuable
  is its **specificity**: "multi-instance" is not a phrase someone types while browsing. It is what someone
  types when they are deciding between in-process fanout and Redis pub/sub, or when in-process fanout has
  already started failing across instances. That is a narrow, expensive decision, and it is exactly the
  class of knowledge a KI corpus exists to hold. The query itself is the evidence that someone hit it.

### Classification: content gaps, not metadata gaps

This agent's remit is to distinguish **missing-KI** from **bad-metadata** candidates, and getting that
backwards wastes effort — retagging cannot fix an empty shelf, and writing a duplicate KI cannot fix a
mistagged one. All three misses here are content gaps, and the evidence is in the registry rather than in
the query text:

- The three matched queries succeeded through tags that closely mirror the query terms
  (`"redis rate limiting"` → `[redis, rate-limiting]`; `"JWT validation middleware"` → `[auth, jwt]`;
  `"OpenTelemetry span adapter"` → `[otel, observability]`). Tagging in this corpus is working.
- For each miss, the registry explicitly records that **no KI exists** with the relevant tag set. That is a
  statement about the corpus contents, not about how existing KIs are labelled. There is no candidate KI
  sitting mistagged and unfound.

Two caveats worth stating rather than glossing:
1. `"JWT validation middleware"` returned exactly **1** hit, matching on `[auth, jwt]` — the token
   `middleware` contributed nothing. `ki-auth-jwt` is a `.claude/knowledge/` (project-scoped) KI, and this
   query is a near-miss rather than a comfortable hit. Not a finding today; worth watching, because a
   corpus where middleware-related queries succeed only via an adjacent term will start missing as it grows.
2. `"redis rate limiting"` returned **2** hits — `ki-redis-sliding-window` and `ki-redis-patterns`. Two
   results for one narrow query is a mild signal of redundancy rather than of coverage. This is the same
   pair `memory-auditor` flagged as a semantic-overlap candidate; noting the agreement, since two
   independent read-only checks reaching the same conclusion is worth more than either alone.

- [ ] **`create-ki` for Expand/Contract migrations** — the phased sequence, `NOT VALID` constraints,
