### Code Snippet — hardcoded/undefined constant (substantive)
The snippet references `RATE_LIMIT_MAX`:

```typescript
return count > RATE_LIMIT_MAX;
```

**`RATE_LIMIT_MAX` is never defined, imported, or explained anywhere in the KI.** Two problems, and the
second is the one that matters:

1. Anyone copying this snippet gets a `ReferenceError`. A KI's code block is copied verbatim far more often
   than it is read carefully.
2. More importantly, the KI never says *what the limit should be* or where it should come from. The
   accompanying `const window = 60_000;` is a magic number inline in the function body — so as written, this
   KI teaches a pattern that hardcodes the window and leaves the threshold undefined. `CLAUDE.md`'s
   magic-number rule and the framework's configuration discipline both apply, and a KI is precisely the
   artifact that propagates a habit: this snippet will be copied into real middleware.

**Recommended (not applied)**: make both values explicit parameters or named constants read from
configuration, and say so in the prose — `isRateLimited(userId, { maxRequests, windowMs })`. A KI that
demonstrates the right shape is worth substantially more than one that demonstrates the mechanism alone.

### Code Snippet — a correctness note worth including
Beyond the constant: the three Redis commands (`ZADD`, `ZREMRANGEBYSCORE`, `ZCARD`) are issued as three
separate round trips and are **not atomic**. Under concurrent requests for the same user, interleaving lets
the count read stale, so the limiter permits bursts above the threshold. The correct implementations use a
Lua script via `EVAL`, or a `MULTI`/pipeline, and the choice has real consequences for whether the limiter
is exact or approximate.

This is not a schema or duplication finding, and it is arguably outside this agent's strict remit — raised
anyway because a KI's purpose is to be copied, and copying this one produces a rate limiter that silently
does not hold its limit. Flagged for a human, not corrected.
