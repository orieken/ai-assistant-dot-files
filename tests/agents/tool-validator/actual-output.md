# Tool Validation Report: summarize-session

## Summary
- Total Skills Validated: **1**

- Missing Dependencies: **1** (an undeclarable-in-this-environment MCP server; see below)

**Verdict: BLOCKER.** One invalid parameter name that will break template interpolation, and one MCP
dependency that is correctly *declared* but makes the skill unusable in exactly the situations where a
session-summary skill is most wanted.

## Findings

### Schema Failures (Critical)

- [`shared/skills/summarize-session/SKILL.md`]: **Invalid parameter name `42_invalid_param`.**

  A parameter identifier beginning with a digit is invalid in every templating and variable-binding syntax
  this framework's skills use. `{{ 42_invalid_param }}` does not parse as an identifier; depending on the
  interpolation engine it either raises at load time or — worse — silently interpolates empty and produces
  a skill that appears to run and quietly does nothing with that value.

  Three further problems with the same parameter, which together suggest it was pasted in rather than
  authored:
  1. **The name reveals no intent.** `42_invalid_param` says nothing about what the value is for. Even with
     a legal identifier, `CLAUDE.md`'s naming rules would reject it.
  2. **It is never referenced in the Instructions.** The body uses `output_path` and `detail_level` and
     never mentions this parameter. A declared, unreferenced, unnamed parameter is dead configuration.
  3. **It has `type: integer` with no `valid_values`, no range, and no `default`** while being
     `required: false` — so its unset behavior is undefined.

  **Recommended: delete it.** If an integer parameter is genuinely needed, name it for what it does, give
  it a default, and reference it in the body.

**Passing, for contrast** — the other two parameters are well-formed and worth recording as the standard the
third fails to meet:
- `output_path` (string, optional, `default: ".claude/session-summary.md"`) — named for its purpose, typed,
  with a sensible default inside the workspace convention.
- `detail_level` (string, optional, `valid_values: ["brief", "full"]`) — constrained enumeration, and both
  values are actually handled in the Instructions. **One gap**: no `default` is declared, so the skill's
  behavior when `detail_level` is omitted is unspecified. The Instructions branch on `"full"` and `"brief"`
  and say nothing about absent. Minor, but it is the difference between defined and accidental behavior —
  recommend `default: "brief"`.

Frontmatter otherwise validates: `name` matches the skill directory, and `description` is a single specific
sentence rather than a category label.

### Missing Script / MCP Dependencies

- [`shared/skills/summarize-session/SKILL.md`]: `standalone: false` with `requires_mcp: ["memory-server"]`.

  **The declaration itself is correct and should be credited.** The skill genuinely depends on an MCP
  server — the Instructions say "Use the `memory-server` MCP tool to retrieve recent context items" — and it
  declares that dependency in frontmatter rather than hiding it in the body. That is exactly the hidden-MCP-
  dependency failure this agent exists to catch, and this skill does **not** commit it. A skill that used
  `memory-server` while claiming `standalone: true` would be the serious finding; that is not what is here.

  The finding is about **consequences, not honesty**:

  1. **`memory-server` availability could not be verified.** No MCP server registry or configuration is
     present in this environment, so this agent cannot confirm the server exists, is installed, or exposes a
     tool matching the described use. Reported as unverifiable rather than as missing — declaring a
     dependency on a server nobody has configured, and declaring one on a standard server, look identical
     from here. **A human must confirm `memory-server` is a real, available server** and not a placeholder
     name.
  2. **`standalone: false` blocks the skill in precisely its best use case.** A session-summary/handoff
     skill is most valuable when a session is ending, context is running out, or work is being handed to
     another person or agent. Those are also the moments most likely to be a plain terminal session with no
     MCP servers attached. A hard MCP requirement means the skill is unavailable exactly when it is wanted.
  3. **The dependency may not be necessary.** The Instructions describe summarizing *the current session* —
     decisions made, tools called. That information is in the conversation the skill is already running
     inside. What `memory-server` adds is "recent context items", which reads like an enhancement rather
     than the core function. **Strongly recommend** restructuring as `standalone: true` with `memory-server`
     as an optional enrichment: summarize from the session by default, and pull additional context when the
     server happens to be available. That is a design change requiring a human decision, not a validation
     fix — raised, not made.
