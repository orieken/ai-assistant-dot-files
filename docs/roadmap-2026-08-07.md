## Epic 69 — MCP Skill Auto-Bundler

**§3 item 1** (extended from Epic 43's Go module scaffold).

Epic 43 (`v3.3.12`) shipped a Go MCP server with 6 M1 tools hardcoded in `cmd/mcp-server`.
The 69 skills in `shared/skills/` are not auto-discovered. This epic adds a skill-bundling
generator: a script reads `SKILL.md` frontmatter and emits MCP tool registration stubs,
so new skills surface as MCP tools without manual wiring.

See `docs/prompts/epic-69-mcp-skill-bundler.md`.

---

## Epic 70 — `health-check --fix` + `install.sh --auto-sync`

**§3 item 2**.

`scripts/health-check.sh` is currently read-only — it reports problems but cannot fix them.
Many FAIL-class checks are deterministic: re-running a generator script would fix them.
This epic classifies all checks into AUTO-FIXABLE vs HUMAN-REQUIRED and implements a `--fix`
flag that remediates only the safe class. `install.sh --auto-sync` applies the same logic at
install time to close parity drift automatically.

See `docs/prompts/epic-70-health-check-autofix.md`.

## Epic 71 — Pipeline TUI / Visual Delivery Dashboard

**§3 item 3**.

`deliver-feature` and `deliver-bugfix` are text-based pipelines with no visual progress
representation. This epic creates an interactive TUI (Go `bubbletea` or Python `rich`) that
reads `pipeline-trace.json` and `pipeline-state.json` to show: current stage, active agent,
elapsed time, estimated token spend, and pending gate approvals. Phase A must resolve the
architectural question of whether the TUI runs as a live sidecar or as a post-hoc reader.

See `docs/prompts/epic-71-pipeline-tui.md`.

## Epic 72 — Dynamic Provider Fallback & Multi-Model Orchestration

**§3 item 4**.

`shared/model-defaults.yaml` maps tiers (light/default/heavy) to one concrete model ID.
Long pipeline runs on heavy or default tier agents are vulnerable to rate limits or API
outages. This epic extends the schema with per-tier fallback chains (e.g., Claude Sonnet →
Gemini 1.5 Pro → GPT-4o) and updates `scripts/resolve-model-tier.py` to emit the full
chain so pipeline orchestrators can retry on the next provider.

See `docs/prompts/epic-72-multi-model-fallback.md`.

## Epic 73 — AOS Policy Engine Completion

**§3 item 5** — partially implemented in AOS Phase 4.

`shared/orchestration/policy-evaluator.md` is a design spec, not a runnable implementation.
`shared/policies/examples/` has 3 sample policies. No `.claude/policies/` directory
(the project-level activation path described in `shared/rules/approval-gates.md`) exists.
This epic implements `scripts/evaluate-policy.sh`, bootstraps `.claude/policies/` with a
real policy, wires the evaluator into `deliver-feature` at the 3 Tier-A gates (`git-commit`,
`out-of-boundary-write`, `fitness-function-wiring`), and adds `health-check.sh` validation.

See `docs/prompts/epic-73-policy-engine-completion.md`.
